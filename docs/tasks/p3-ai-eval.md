# Task p3-ai-eval: "AI answer leads to the right minute" evaluation + CI job with real Gemma 4

## Scope
tools/Murmur.AiEval/** (new console project, add to Murmur.sln), tests/fixtures/** (new), .github/workflows/** (new job or workflow), docs/CI.md

## Spec
Phase-3 criterion (docs/PLAN.md): the AI answer must lead to the correct minute of the recording. Build an automated, repeatable evaluation.
1. Fixture tests/fixtures/meeting-60min.json: a realistic ~60-minute meeting transcript (Ukrainian with some English terms, two speakers Me/Others, segments of 3–15 s with word timings evenly spread, ~600+ segments). Plant >= 12 distinct, unambiguous facts at known times spread over the hour (e.g. "бюджет на Q3 затвердили — 1,2 млн гривень" at 07:42; "реліз переносимо на 14 березня" at 23:10; "відповідальна за міграцію бази — Оксана" at 41:05 …), surrounded by plausible filler talk that does NOT repeat the facts. Also tests/fixtures/meeting-60min.questions.json: 12 questions (paraphrased, not verbatim) with the expected time of the fact and acceptable tolerance ±60 s; 2 of them deliberately unanswerable (expected: the model says it is not in the recording — no citation required). Generate the fixture with a deterministic script you commit (tools/Murmur.AiEval/FixtureGen or a Python script under tools/) — no LLM needed.
2. tools/Murmur.AiEval (console): `Murmur.AiEval --fixture <json> --questions <json> --out <json> [--data-dir <tmp>]`: creates a temp SqliteStorage, a session, SaveTranscriptAsync(fixture), LocalLlm.FromEnvironment() (Murmur.Intelligence) + Assistant, IndexSessionAsync, then for each question AskAsync (scope = the session) collecting the full answer and citations; pass if any citation's time is within tolerance of the expected time (unanswerable: pass if no confident citation AND the answer says it is not found — simple keyword check in UA/EN); prints a markdown table (question, expected, cited, pass, latency, first 120 chars of the answer) and writes JSON {passed, total, rate, perQuestion[], model files, timings: indexMs, avgAnswerMs}; exit code 0 if rate >= 0.8 else 1. Also `--retrieval-only` mode: no chat model — checks that the hybrid SearchAsync top-3 contains the planted fact's chunk (fast sanity check, needs only the embedding model, or only keyword search when no embedding model).
3. CI: job `ai-eval` (ubuntu-latest, 16 GB runner, timeout 60, after linux build) — run scripts/fetch-models.sh --ai (cache <models>/llama.cpp and <models>/gguf with actions/cache), export MURMUR_LLM_MODEL/MURMUR_EMBED_MODEL/MURMUR_LLAMA_SERVER, run the eval, publish the table to $GITHUB_STEP_SUMMARY and upload the JSON; the job fails when rate < 0.8. Trigger: push to night-run/master and workflow_dispatch. (A Windows variant is optional — add it as workflow_dispatch-only if cheap.)
4. Locally (no GGUF models here): run the eval in `--retrieval-only` keyword mode against the fixture to prove the plumbing (report), and unit-test the fixture generator determinism and the scoring logic (tests may live in tests/Murmur.Intelligence.Tests if you add a reference to the tool's scoring code, or keep scoring in the tool and add a small tests project — choose the simplest).
Depends on: Murmur.Intelligence (LocalLlm, Assistant) and Storage search (SearchKeywordAsync / SearchVectorAsync) — they are merged before this task runs; read their code for the exact APIs and the fetch-models --ai contract (models.json, env vars).

## Acceptance
Build 0 warnings; fixture + questions committed; retrieval-only run passes locally; CI job YAML valid.
