# Task p1-core-audio: Core audio pipeline: lock-free ring, resampler, crash-safe WAV, Recorder, recovery, synthetic capture

## Scope
src/Murmur.Core/** (new files only; architect interfaces stay unchanged), tests/Murmur.Core.Tests/**, tests/Murmur.Benchmarks/**, optionally one small helper console under tests/ for the crash test (add it to Murmur.sln)

## Spec
Everything here is platform-neutral and must be fully testable on Linux.
1. Murmur.Core.Audio.AudioRingBuffer: lock-free single-producer/single-consumer float ring, power-of-two capacity. `int Write(ReadOnlySpan<float>)` writes what fits and returns the count (overflow is added to `long DroppedSamples`), `int WriteZeros(int count)`, `int Read(Span<float>)`, `int Available`. Cache-line padded head/tail, Volatile reads/writes only, no locks, no allocations after construction.
2. Murmur.Core.Audio.CaptureTrack : IAudioSink — one per audio source: owns a ring of >= 4 s of source audio (frames*channels), computes the peak (max |x|) while copying and publishes it lock-free (Volatile float bits) for the orb, counts frames written/dropped. Write/WriteSilence: zero allocations, no locks, no logging, no LINQ.
3. Murmur.Core.Audio.StreamingResampler (+ downmix): interleaved N-channel float at any rate -> mono 16 kHz float. Windowed-sinc (Kaiser or Blackman-Harris, >= 16 zero crossings per side), cutoff ~0.45*16 kHz, stateful across calls (any chunking yields the same output as one-shot), no long-run drift (after T s of input the output length is round(T*16000) +/- latency, independent of chunking), integer fast path for 48k->16k, pass-through for 16k mono. Zero allocations after construction.
4. Murmur.Core.Audio.WavPcm16Writer: crash-safe 16-bit PCM WAV writer (mono 16 kHz by default). 44-byte header, Append(ReadOnlySpan<float>) converts with clipping into a preallocated byte buffer, Flush() rewrites RIFF/data sizes and calls FileStream.Flush(flushToDisk: true). Murmur.Core.Audio.WavRepair.TryRepair(path, out TimeSpan duration) fixes header sizes from the real file length (dropping a partial trailing sample). Murmur.Core.Audio.WavReader: reads PCM16/float32 WAV of any rate/channels (used by tests and later by ASR).
5. Murmur.Core.Recording.Recorder : IRecorder. ctor(ICapture capture, ISessionStore store, TimeProvider time, RecorderSettings settings) with settings FlushInterval 2 s, WriterPeriod 20 ms, RingSeconds 4. StartAsync: creates the session via ISessionStore (default title "Запис yyyy-MM-dd HH:mm"), creates requested IAudioSources (Microphone kind = mic.wav / Speaker Me; SystemOutput kind = system.wav / Others), a CaptureTrack per source, starts sources, then ONE dedicated writer thread (a real Thread, not the thread pool, not async) that every WriterPeriod drains each ring -> resampler -> WavPcm16Writer at ISessionStore.GetFiles(id) paths, flushes every FlushInterval, updates Stats. Contract (document it on the type): every IAudioSource emits a wall-clock-continuous stream from Start() (gaps are filled with WriteSilence by the source), so the recorder does not pad. Screen: when options.Screen and capture.Capabilities.Screen, create one IScreenRecorder and StartSegmentAsync(files.ScreenSegment(n)); SetScreenEnabledAsync toggles segments and records ScreenSegment(Index, Offset, Duration) into the session. Levels = track peaks with decay; Elapsed from TimeProvider. StopAsync: stop sources (joins capture threads) -> final drain -> flush + dispose writers -> stop screen segment -> UpdateSessionAsync(Duration = longest track, State Recorded, HasMicrophone/HasSystemAudio, ScreenSegments) -> return the record. Faults: IAudioSource.Faulted marks the track faulted and the writer keeps it aligned with silence for elapsed wall time; if every audio track failed, stop with State Failed + Error. Start/Stop are serialized; StateChanged raised on transitions. Steady-state writer loop allocates nothing (preallocated buffers).
6. Murmur.Core.Recording.RecoveryService: at app start, for every session still in State Recording (the app died): WavRepair each track, Duration from the WAVs, State Interrupted; returns the recovered sessions.
7. Murmur.Core.Capture.Synthetic.SyntheticCapture : ICapture — for Linux development, the Linux Desktop target and tests. "Microphone" and "System" devices produce deterministic 48 kHz stereo float signals (mic: 440 Hz sine with slow AM; system: a sample-index-coded signal that lets tests detect gaps/repeats) from a dedicated thread at real-time pace, with an optional speed factor (e.g. x120) for accelerated tests, honoring the wall-clock continuity contract. CreateScreenRecorder returns a NullScreenRecorder (creates the segment file, no frames); Capabilities.Screen configurable (default false).
8. Tests in tests/Murmur.Core.Tests: ring (wraparound, overflow accounting, 2-thread stress with >= 10^8 samples verifying sequence integrity); resampler (1 kHz sine 48k->16k keeps frequency and amplitude within 0.5 dB; a 12 kHz tone is attenuated > 40 dB; chunked == one-shot; exact long-run counts for 44.1k and 48k inputs); WAV writer/repair (header fields, truncated file repaired, flush durability); Recorder with SyntheticCapture (start/stop, screen toggling with segment offsets, a faulted source, both faulted -> Failed); RecoveryService. ACCEPTANCE TEST "1 hour without losses": the full Recorder pipeline over 1 hour of synthetic audio in accelerated mode (speed factor or a controllable TimeProvider — keep the real threads) asserting mic.wav and system.wav each hold 3600 s x 16000 samples (+/- resampler latency), Stats.DroppedFrames == 0 and continuity of the coded system signal (no gaps/repeats). CRASH TEST: kill a real child process while it records (simplest robust way, e.g. a tiny helper console under tests/ that runs Recorder+SyntheticCapture into a temp dir with an in-memory/simple ISessionStore), then run WavRepair/RecoveryService and assert >= (elapsed - 2.5 s) of audio survived and the WAV is valid.
9. Benchmarks in tests/Murmur.Benchmarks ([MemoryDiagnoser]): ring write+read of 10 ms chunks, CaptureTrack.Write (48 kHz stereo, 10 ms), resampler 48k stereo -> 16k mono per 10 ms, WAV append 10 ms. All hot paths must report 0 B allocated. Report the numbers.

## Acceptance
Build 0 warnings; all Core tests green including the 1-hour accelerated no-loss test and the kill-the-process crash test; benchmarks show 0 B/op on the hot paths (numbers in measurements).
