# Task p1-wasapi: WASAPI microphone + loopback capture with own thin interop

## Scope
src/Murmur.Capture.Windows/** (audio + WindowsCapture facade), tests/Murmur.Capture.Windows.Tests/**

## Spec
Production version of the phase-0 spike's capture path (see spikes/Murmur.Spike.LoopbackAsr for a starting point, but production quality).
1. Own thin interop only: [GeneratedComInterface] + StrategyBasedComWrappers and [LibraryImport] (ole32 CoInitializeEx/CoCreateInstance/CoTaskMemFree/PropVariantClear, avrt AvSetMmThreadCharacteristicsW/AvRevertMmThreadCharacteristics, kernel32 CreateEventW/SetEvent/WaitForMultipleObjects/CloseHandle/QueryPerformanceCounter/QueryPerformanceFrequency). COM: IMMDeviceEnumerator, IMMDeviceCollection, IMMDevice, IPropertyStore (PKEY_Device_FriendlyName), IAudioClient, IAudioCaptureClient. Verify every vtable order and struct layout against mmdeviceapi.h, audioclient.h, mmreg.h, propsys.h and list what you checked in notes. No third-party audio libraries.
2. Murmur.Capture.Windows.WindowsCapture : ICapture — Capabilities(Microphone: any active capture endpoint, SystemAudio: any active render endpoint, Screen: false for now — another task adds the screen recorder; CreateScreenRecorder throws NotSupportedException and GetDisplays returns [] until then). GetAudioDevices(kind): EnumAudioEndpoints(eCapture/eRender, DEVICE_STATE_ACTIVE) with friendly names and IsDefault (GetDefaultAudioEndpoint(.., eConsole)). CreateAudioSource(kind, id) (null id = default device).
3. WasapiAudioSource : IAudioSource — shared mode, event-driven (AUDCLNT_STREAMFLAGS_EVENTCALLBACK; plus AUDCLNT_STREAMFLAGS_LOOPBACK on render endpoints), ~20 ms buffer, mix format (float32 or PCM16/24/32 -> float into a preallocated buffer; WAVE_FORMAT_EXTENSIBLE handled). Dedicated capture thread: COM MTA, MMCSS task "Audio"; loop WaitForMultipleObjects({audioEvent, stopEvent}, 100 ms) -> drain every packet: GetBuffer(data, frames, flags, devicePos, qpcPos) -> SILENT flag => sink.WriteSilence(frames) else convert => sink.Write(span) -> ReleaseBuffer. Wall-clock continuity contract (see IAudioSink docs and the Recorder): track frames emitted since Start(); with QPC compute the frames expected by now; when packets don't arrive (idle loopback delivers nothing while nothing plays) or after AUDCLNT_BUFFERFLAGS_DATA_DISCONTINUITY, emit WriteSilence for the missing frames once they exceed a threshold (~2 buffer periods), never emit ahead of wall clock, and keep the stream aligned when real packets resume (use the packet qpcPos to place them). Zero allocations, no locks, no logging, no LINQ, no async in the loop. Stop(): set stop event, join, IAudioClient.Stop, release COM objects, close handles; idempotent. Errors (e.g. AUDCLNT_E_DEVICE_INVALIDATED) raise Faulted once and the thread exits cleanly. Dispose = Stop + release.
4. Pure helpers (format parsing, sample conversion, gap math) in separate internal static classes that compile and run on any OS so they are unit-testable on Linux (InternalsVisibleTo the test project).
5. Tests in tests/Murmur.Capture.Windows.Tests: Linux-runnable unit tests for the helpers (PCM16/24/32/float conversion, WAVEFORMATEXTENSIBLE parsing from bytes, gap computation incl. resume after silence and never-ahead); Windows-only tests [Trait("Category","Windows")] skipped elsewhere: enumerate devices; when a render endpoint exists, capture 3 s of loopback through a counting IAudioSink and assert 3 s +/- 150 ms of frames were delivered even if nothing plays (gap fill); same for the microphone when a capture endpoint exists (skip with a message otherwise).
6. The project stays trim/AOT-analyzer clean (IsAotCompatible, warnings = errors).

## Acceptance
Linux: build 0 warnings, helper tests green, vtables/structs checked and listed in notes. Windows behaviour UNVERIFIED until CI runs the Windows-trait tests.
