# Task p1-screen: Screen capture: Windows.Graphics.Capture -> Media Foundation H.264 (GPU, zero-copy), fragmented MP4 segments

## Scope
src/Murmur.Capture.Windows/** (screen files + WindowsCapture.GetDisplays/CreateScreenRecorder/Capabilities.Screen), tests/Murmur.Capture.Windows.Tests/**, Directory.Packages.props (Vortice.* only)

## Spec
1. Displays: EnumDisplayMonitors + GetMonitorInfoW ([LibraryImport] user32) -> DisplayInfo(Id = monitor device name like \\.\DISPLAY1, Name, Width, Height, IsPrimary).
2. WgcScreenRecorder : IScreenRecorder. D3D11 device with BGRA + VIDEO_SUPPORT (hardware; WARP fallback) — Vortice.Direct3D11 / Vortice.DXGI / Vortice.MediaFoundation 3.8.3 (MIT) are allowed if they are AOT/trim clean (check: AOT-publish a throwaway linux-x64 console that references and touches them — the IL is platform-neutral so ILC reports warnings — and record the result; if they warn, write the needed interop yourself with [GeneratedComInterface]). WinRT: IDirect3DDevice via CreateDirect3D11DeviceFromDXGIDevice, GraphicsCaptureItem via IGraphicsCaptureItemInterop.CreateForMonitor (activation factory interop through CsWinRT, AOT-safe), Direct3D11CaptureFramePool.CreateFreeThreaded(B8G8R8A8UIntNormalized, 2 buffers, size), GraphicsCaptureSession with IsCursorCaptureEnabled = true and IsBorderRequired = false where the API exists (ApiInformation check).
   FrameArrived (free-threaded): rate-limit to FrameRate (drop extras, count), get the ID3D11Texture2D (IDirect3DDxgiInterfaceAccess), GPU-copy into a texture from a small pool (no CPU readback — zero-copy to the encoder), wrap with MFCreateDXGISurfaceBuffer -> IMFSample (sample time = SystemRelativeTime - segment start, duration 1/fps) and hand it to the sink writer on an encoder thread through a bounded queue (drop + count when full, never block FrameArrived). Content size change: recreate the frame pool; keep the encoder size (scale/letterbox via the GPU or keep native size and note).
   Sink writer: MFStartup once; IMFDXGIDeviceManager (MFCreateDXGIDeviceManager + ResetDevice); attributes MF_READWRITE_ENABLE_HARDWARE_TRANSFORMS=1, MF_SINK_WRITER_D3D_MANAGER, MF_TRANSCODE_CONTAINERTYPE = MFTranscodeContainerType_FMPEG4 (fragmented MP4 so a crash leaves a playable file), MF_LOW_LATENCY; output MFVideoFormat_H264 (MF_MT_AVG_BITRATE = BitrateKbps*1000, frame size <= MaxHeight keeping aspect (even dimensions), frame rate, progressive, PAR 1:1, Main or High profile); input MFVideoFormat_ARGB32/RGB32. Prefer the hardware encoder; fall back to software H.264 (MF software encoder) if needed; Stats.Encoder names the one in use. StopSegmentAsync -> Finalize; DisposeAsync releases everything. Faults -> Faulted event.
3. WindowsCapture.Capabilities.Screen = GraphicsCaptureSession.IsSupported(); GetDisplays/CreateScreenRecorder implemented.
4. Tests (Windows trait, skipped elsewhere): record a 3 s segment of the primary display -> file exists and > 10 KB; open it with IMFSourceReader and assert an H.264 stream, duration ~3 s (+/- 0.5 s), >= 1 frame; two consecutive segments (toggle). If WGC or Media Foundation are unavailable on the machine (e.g. no desktop session / Server without Media Foundation), the test must skip with an explicit message (never pass silently) so CI shows it. Linux-runnable unit tests for pure helpers (even-size scaling math, timestamp conversion, frame-rate limiter).
5. Stay trim/AOT-analyzer clean; note in detail anything that can only be verified by the win-x64 AOT publish in CI.
