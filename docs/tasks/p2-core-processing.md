# Task p2-core-processing: ASR client, job queue, post-recording processing, peaks, dev player

## Scope
src/Murmur.Core/** (new files; architect interfaces unchanged), tests/Murmur.Core.Tests/**, tests/Murmur.Benchmarks/** (only if a hot path appears)

## Spec
The ASR worker process (src/Murmur.Transcription, being finished in parallel) implements the protocol in src/Murmur.Core/Transcription/Protocol/WorkerProtocol.cs. Build the app side in Core:
1. `Murmur.Core.Transcription.ModelLocator`: models dir = env MURMUR_MODELS_DIR, else LocalApplicationData/Murmur/models; Parakeet dir `sherpa-onnx-nemo-parakeet-tdt-0.6b-v3-int8` (encoder.int8.onnx, decoder.int8.onnx, joiner.int8.onnx, tokens.txt), VAD `silero_vad.onnx`; `IsAsrInstalled`.
2. `Murmur.Core.Transcription.WorkerAsrClient : IAsr, IAsyncDisposable`: worker path = env MURMUR_TRANSCRIPTION_WORKER, else `Murmur.Transcription(.exe)` next to the app (AppContext.BaseDirectory); if the path is a .dll run it with `dotnet <dll>` (dev/tests). Starts the worker lazily (`--serve --model-dir --vad --threads --idle-exit-seconds 120`), waits for `ready`, sends `transcribe`, streams `segment` events as TranscriptSegment (speaker from the request; times -> TimeSpan; words), reports `progress` via IProgress<AsrProgress>, completes on `done`, throws on `error`. Cancellation -> sends `cancel`, then kills the worker if it does not answer within 5 s. Worker crash mid-job -> exception with the stderr tail; the next request starts a fresh worker. One job at a time (serialize). Status: ModelMissing when ModelLocator says so, Busy during a job, else Idle. STJ source-gen (WorkerJsonContext) only. Test it against a fake worker: a tiny script/console that speaks the protocol (e.g. a test helper project under tests/ added to Murmur.sln, or `dotnet` + a C# file) — plus, when the real worker and models are available (MURMUR_MODELS_DIR or /root/models and the built src/Murmur.Transcription), an integration test on test_wavs/en.wav (skip otherwise).
3. `Murmur.Core.Jobs.JobQueue`: priority queue (Transcription > Indexing > Summary), a single background consumer, `Enqueue(priority, name, Func<CancellationToken, Task>)`, `Paused` while a recording is in progress (heavy work never overlaps recording — CLAUDE.md), resumes after; cancellation on dispose; exceptions captured per job; observable status (pending/running counts, current job name) via an event raised off the consumer thread.
4. `Murmur.Core.Processing.SessionProcessor`: subscribes to IRecorder.StateChanged; after a recording stops (and for sessions passed to `EnqueueAsync(SessionId)`), enqueues: build peaks -> transcribe -> save -> (indexing hook, see below). States: Transcribing -> Transcribed; Failed with Error on failure. Transcribes the mic track as Speaker.Me and the system track as Speaker.Others (only tracks that exist), merges segments by Start, saves via ITranscriptStore with Engine "parakeet-tdt-0.6b-v3-int8". Optional indexing hook: ctor accepts `Func<SessionId, CancellationToken, Task>? indexer` (phase 3 passes IAssistant.IndexSessionAsync) run as an Indexing job -> State Ready; when null, Transcribed is final until phase 3 (set Ready after transcription when no indexer is configured). Startup recovery: `ResumePendingAsync()` re-enqueues sessions in Recorded/Transcribing state. Progress per session (0..1) exposed for the UI (event + `GetProgress(SessionId)`). ASR not installed -> leave the session Recorded and expose a clear status ("Модель Parakeet не встановлена").
5. `Murmur.Core.Audio.PeaksBuilder`: from one or more 16 kHz mono WAVs build `peaks.bin` (SessionFiles.Peaks): header (magic "MPK1", peaksPerSecond = 50, count) + one byte per window = max |sample| of the louder track scaled to 0..255; streaming read (no full-file load); `PeaksFile.Read(path)` returns the bytes. Test with synthetic WAVs.
6. `Murmur.Core.Capture.Synthetic.ClockAudioPlayback : IAudioPlayback` / `ClockAudioPlayer : IAudioPlayer`: dev/test player for Linux — no sound, Duration from WAV headers, Position advances with a TimeProvider while Playing, Seek/Pause/Ended semantics identical to what a real player must do (document the contract on the class; the Windows WASAPI player will follow it).
7. Tests for everything above (fake worker, queue priorities/pausing/cancellation, processor state machine incl. failure and recovery, peaks correctness, clock player semantics).
