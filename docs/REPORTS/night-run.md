| [39118252885](https://github.com/skyp1nus/Murmur/actions/runs/39118252885) | з D-028 | **11/12 (92%)** ✅ | 90,4 с | усі `stop`, 24–55 токенів; 1 промах пошуку (q10) |

Діагноз і фікс (D-028): `LlamaChatClient` мовчки відкидав `reasoning_content`, а модель витрачала бюджет `max_tokens` на приховане «мислення» — звідси порожні відповіді й обриви посеред слова, причому більше на повільнішому CPU. Тепер `Assistant` просить модель не думати (`ChatOptions.Reasoning = None` → `chat_template_kwargs.enable_thinking=false`), «мислення», якщо воно є, приходить окремим `TextReasoningContent`, а eval пише для кожного питання причину зупинки й токени (колонка «Generation»). Прямо виміряти «мислення» до фіксу не вийшло (eval тоді його не логував) — висновок зроблено з обривів, часу й результату після фіксу.

Чесні застереження: усі 9 зарахованих відповідних питань модель процитувала сама (часова мітка в тексті відповіді, не запасна цитата), але відповідь на q02 починається з «немає інформації» і лише далі називає дизайнера. Відповідь ~90 с на 4 vCPU без GPU, майже весь час — обробка промпту: для зручного чату потрібен GPU, швидший CPU, менше уривків у промпті або Gemma E2B (BACKLOG).

## Відкриті ризики й BLOCKED

1. **Фаза 2, швидкість ASR:** 1 год → 89,5 с на 4 vCPU Zen 5, але 197–227 с на 4 vCPU Zen 3 (бюджет 180 с). На старших CPU без VNNI бюджет не гарантований. Варіанти: перевірити на цільовому ПК (чекліст, крок 6); DirectML/CUDA-провайдер ONNX Runtime; тюнінг VAD (менше декодування тиші — реальні мітинги мають більше пауз, ніж бенч-сигнал). Workflow `asr` червоніє на гейті бюджету щоразу, коли потрапляє на раннер Zen 3, — це очікувано.
2. **Екран на машині без GPU:** на windows-latest (WARP) WGC віддає кадри, але zero-copy шлях неможливий → додано CPU-readback (D-027). Фінальну перевірку CPU-readback і **zero-copy з апаратним енкодером на справжньому GPU** CI не дає — лише ручна перевірка (чекліст, кроки 1 і 4).
3. **Мікрофон на CI** заборонено політикою конфіденційності → реальний захоплений мікрофон перевірявся лише юніт-тестами і логікою пропуску; loopback перевірено на віртуальній карті.
4. **CPU-бюджети запису** виміряні на 4-vCPU VM без GPU (сфера малюється CPU, кадри екрана копіюються в системну пам'ять і кодуються програмно) — це песимістична оцінка. Лише аудіо — 1,25% з великим запасом; з екраном два 60-секундні прогони дали 6,15% і 9,25% (бюджет 8%) — на CI це на межі. Цифри на реальному ПК з GPU — чекліст, крок 4.
10. **Avalonia 12.1.4 + Native AOT:** ILC друкує два повідомлення «will always throw» для `Avalonia.Win32.DComposition` (`CreateTargetForHwnd`, `bool` у `UnmanagedCallersOnly`). Це керовані vtable для COM-інтерфейсу, який реалізує Windows, а не застосунок; гейт попереджень їх не ловить, застосунок стартує й малює (startup, capture-e2e). Перевірити після оновлення Avalonia.
5. **Gemma 4 / EmbeddingGemma GGUF** — назви репозиторіїв на Hugging Face не можна було перевірити з цього середовища (HF заблоковано); `fetch-models -Ai` пробує кілька кандидатів. Ліцензія EmbeddingGemma (Gemma Terms of Use) — перевірити до релізу (THIRD-PARTY-NOTICES).
6. **Вектори**: P2 з рев'ю — пошкоджений рядок `chunks` однієї сесії ламає бібліотечний векторний пошук до переіндексації (не виправлено, у BACKLOG).
7. **.NET 11 RC2 / Avalonia 12.1.4** — оновитись на GA (листопад 2026); BenchmarkDotNet 0.15.8 ще не знає net11.0 (бенчмарки in-process, D-011).
8. **Вкладка «Резюме»** — заглушка (резюме/action items — опційний пункт пайплайна, не входив у критерії фаз 0–3).
9. **Темна тема й нові макети з master** (`f3155cb`, `2174f76`: `colorDark` у `tokens.json`, макети онбордингу/налаштувань) з'явились після відгалуження `night-run` — у цій гілці не реалізовані (UI лише у світлій темі). Мерж із master чистий, тести App (225) на змерженому дереві зелені: генератор токенів поки ігнорує `colorDark`.

## Чекліст для Windows (завтра)

Потрібно: Windows 11 x64 (бажано з GPU — перевірити zero-copy шлях екрана), мікрофон і динаміки/навушники, PowerShell 7 (`pwsh`), ~8 ГБ вільного місця для моделей.

**0. Доступ до мікрофона.** Параметри → Конфіденційність і безпека → Мікрофон → увімкнути «Доступ до мікрофона» і «Дозволити класичним програмам доступ до мікрофона». (Без цього Murmur пише лише системний звук і показує попередження — це теж варто побачити один раз.)

**1. Отримати збірку** — один із варіантів:
- **A (швидко):** GitHub → Actions → workflow `ci` → останній запуск на гілці `night-run` → Artifacts → `murmur-win-x64` → розпакувати, напр. у `C:\Murmur`. Там `Murmur.exe`, `Murmur.Transcription.exe` і нативні бібліотеки.
- **B (з коду):** встановити .NET SDK `11.0.100-rc.2.26504.105` (точна версія з `global.json`), потім у корені репо:
  ```powershell
  git checkout night-run
  dotnet build Murmur.sln -c Release          # очікуємо 0 warnings
  dotnet test Murmur.sln -c Release           # Windows-тести тут виконуються по-справжньому
  dotnet publish src/Murmur.Desktop -c Release -f net11.0-windows10.0.22621.0 -r win-x64 -o C:\Murmur
  ```
  Що побачити: build без попереджень; у `dotnet test` тести з `Category=Windows` **пройшли**, а не пропущені (на CI в `capture-e2e` пройшли 406 із 409, пропущені лише 3 мікрофонні — там мікрофон заборонений політикою) — особливо `WindowsCaptureTests` (мікрофон/loopback 3 с), `WgcScreenRecorderTests` (H.264-файл), `WasapiPlaybackTests`.

**2. Моделі.** `pwsh scripts/fetch-models.ps1` → Parakeet (~0,67 ГБ) і Silero VAD у `%LOCALAPPDATA%\Murmur\models`. Для AI: `pwsh scripts/fetch-models.ps1 -Ai` → llama.cpp `llama-server` і GGUF Gemma 4 E4B + EmbeddingGemma (~5–6 ГБ; шлях запишеться в `models\gguf\models.json`, застосунок прочитає його сам).

**3. Старт < 400 мс.** `pwsh scripts/measure-startup.ps1 -Exe C:\Murmur\Murmur.exe -Runs 7` → таблиця, медіана має бути < 400 мс. Потім просто запустити `Murmur.exe`: відкривається «Бібліотека» (порожній стан «Ще немає записів», пошук-пілюля, шрифти Inter/Geist Mono, жодного синього/помаранчевого поза сферою).

**4. Запис.** «Новий запис» → екран запису. Перевірити списки пристроїв (мікрофон, вихід). Увімкнути «Мікрофон» і «Системний звук», «Почати запис». Увімкнути відео з мовленням (YouTube) і говорити самому.
- Очікуємо: сфера «дихає» в такт звуку, таймер іде (Geist Mono), підказка «Попередь учасників…».
- Посередині запису натиснути «Екран» (увімк.), через ~30 с — вимк., ще раз увімк.
- Відкрити Диспетчер завдань → `Murmur.exe`: CPU лише аудіо < 3%, з екраном < 8%, пам'ять < 150 МБ.
- «Зупинити» → запис у бібліотеці з бейджами мікрофон / звук / екран.
- Папка `%LOCALAPPDATA%\Murmur\Recordings\<дата>_<id>`: `mic.wav`, `system.wav` (16 кГц моно — відкриваються будь-яким плеєром, голос чути, тривалість = тривалість запису), `screen-000.mp4`, `screen-001.mp4` (відкриваються в «Кіно й ТБ», показують екран).

**5. Аварійне завершення.** Почати запис, через ~20 с у Диспетчері завдань «Завершити завдання» для `Murmur.exe`. Запустити знову → запис у бібліотеці з бейджем «Перервано», WAV-и відтворюються до моменту вбивства (втрата ≤ 2–3 с).

**6. Транскрипція.** Після «Зупинити» запис отримує бейдж «Транскрибується N %» → «Готово». Відкрити запис: ліворуч плеєр із waveform, праворуч транскрипт з мітками «Я» / «Інші» і часом. «Відтворити» → підсвічується поточне слово; клік по слову → перемотка туди. Перевірити українську й англійську.
- Швидкість на вашому CPU (критерій фази 2: на CI пройдено лише на раннері Zen 5):
  ```powershell
  $m="$env:LOCALAPPDATA\Murmur\models"; $p="$m\sherpa-onnx-nemo-parakeet-tdt-0.6b-v3-int8"
  C:\Murmur\Murmur.Transcription.exe --bench --model-dir $p --vad "$m\silero_vad.onnx" --wav "$p\test_wavs\en.wav,$p\test_wavs\de.wav,$p\test_wavs\es.wav,$p\test_wavs\fr.wav" --seconds 3600 --out bench.json
  ```
  Очікуємо `transcribeMs` < 180000 (на CI, 4 vCPU: 89,5 тис. на Zen 5, 197–227 тис. на Zen 3). У `bench.json` поле `machine.cpu` покаже модель процесора.

**7. AI.** (після `fetch-models.ps1 -Ai`, перезапустити Murmur) Відкрити транскрибований запис → вкладка «Запитати AI» → питання про щось, що звучало в записі. Очікуємо: відповідь з'являється частинами, під нею чипи `12:34`; клік по чипу → плеєр стрибає на цей момент і грає, і там справді звучить відповідь. Під час нового запису вкладка має показувати «AI на паузі», а `llama-server.exe` у Диспетчері завдань — зникнути. У бібліотеці: пошук «слово з запису» → результати з чипами часу; «Запитати AI по всіх записах» → чат по всіх записах, чип відкриває потрібний запис.

**8. Годинний запис (опційно: критерій фази 1 на вашому ПК і з мікрофоном; на CI вже пройдено).** `C:\Murmur\Murmur.exe --autorecord 3600 --perf-out perf.json`, під час запису грає звук і ви говорите; потім `pwsh scripts/check-recording.ps1 -PerfJson perf.json -CpuBudgetPct 3 -RamBudgetMb 150` → `droppedFrames = 0`, тривалість `system.wav` = 3600 ± 1 с, CPU і RAM у бюджеті.

Якщо щось не так — найкорисніше: скриншот + `perf.json`/вивід команди + версія Windows і модель CPU/GPU.
