# p41-reduced-motion — системне «зменшення анімації»

Гілка `feat/reduced-motion` (від `phase4.1`, `da0402e`). Застосунок слідує налаштуванню Windows **Параметри → Спеціальні можливості → Візуальні ефекти → Animation effects**: коли воно вимкнене, декоративна анімація стоїть.

## Що рухається і що зупиняється

| Елемент | Під «зменшеною анімацією» |
| --- | --- |
| `GlassOrbControl` (орб запису, велкам, голосовий орб онбордингу, вордмарк): «дихання» 3,6 с і пульс за рівнем голосу | Зупиняється: нерухомий кадр канвасу (масштаб 1, ореол без згасання), таймер 15 Гц вимкнено. |
| `OrbControl` (орб «About» у налаштуваннях): дихання й пульс за рівнем | Зупиняється: статичний кадр спокою, таймер вимкнено. |
| `OrbDisc` | Не анімований, без змін. |
| `LevelMeterControl` (смужки рівня мікрофона й системного звуку), `LevelHistoryControl`, `WaveformControl`, прогрес завантаження моделей | Продовжують оновлюватись: несуть інформацію. |
| Таймери `SessionView` / `RecordingView` (позиція відтворення, час запису), `VideoSurface` (кадри відео) | Без змін: це дані, не декорація. |
| Перемикання екранів / `Transitions` / `Animation` в AXAML | Таких анімацій у застосунку немає (перевірено пошуком). |

Орб запису під налаштуванням виглядає однаково в записі й у спокої; стан запису видно за смужками рівня, таймером і кнопками.

## Як підключено

- **Core**: `IMotionPreference` (готовий контракт, не змінювався).
- **Windows** (`Murmur.Capture.Windows/Platform/WindowsMotionPreference.cs`): `ReduceMotion = !SPI_GETCLIENTAREAANIMATION` (`LibraryImport`, AOT-безпечно; невдалий виклик = «анімація ввімкнена»). Читається щоразу, без кешу. `Changed` потребує вікна для `WM_SETTINGCHANGE`; воно приходить лише **верхньорівневим** вікнам (message-only його не отримують), тому вікно хоткеїв не підходить: клас має власне приховане вікно в потоці `Murmur.MotionPreference`, який стартує з першим підписником. На кожне `WM_SETTINGCHANGE` значення читається знову, `Changed` піднімається (у цьому потоці) лише коли воно змінилось; виняток підписника ковтається, інші підписники отримують подію. `Dispose` завершує потік. Фабрика: `WindowsCapture.CreateMotionPreference()`.
- **Desktop**: `CompositionRoot.CreateMotionPreference()` — Windows-реалізація під `#if WINDOWS`, інакше `FullMotionPreference`; кладеться в `AppServices.Motion` (нове необовʼязкове поле в кінці запису), знищується разом із коренем.
- **App**: без статичних сховищ і рефлексії. `Motion.ReduceMotionProperty` — успадковувана приєднана властивість Avalonia. `MotionFollower` (App/Services) ставить її на `MainWindow` при старті й на кожен `Changed` (з потоку Windows) переносить значення в UI-потік через `Dispatcher.UIThread.Post`. Орби слухають зміну властивості у власному `OnPropertyChanged`: при вмиканні показують кадр спокою й зупиняють таймер, при вимиканні (і активному орбі) запускають заново з нуля. Прямі виклики `Update`/`Tick` під налаштуванням нічого не роблять. Тест на нуль алокацій орба не чіпали, він зелений. Прибрано `TODO(reduced-motion)`.
- **Документ**: рядок «2 · Запис (орб)» у `docs/design/DEVIATIONS.md` оновлено.

## Тести

- App `ReducedMotionTests` (10): обидва орби під налаштуванням без таймера й зі статичним кадром (з джерелом рівня і без), перемикання під час роботи зупиняє й відновлює, активація під час reduced, смужка рівня продовжує опитування й слідує за рівнем, `MotionFollower` (початкове значення, перенесення через `post`, відписка, дія через вікно на орб), `FullMotionPreference`.
- Desktop `MotionPreferenceCompositionTests` (1): композиція дає `FullMotionPreference` на портативній збірці.
- Capture.Windows `WindowsMotionPreferenceTests` (10): 6 без нативного коду, 4 з трейтом `Windows` (читання SPI, подія на `WM_SETTINGCHANGE` лише при зміні й не в потоці виклику, `Dispose` завершує потік, підписник, що кидає виняток). Нативні 4 тут пропущено, їх проганяє Windows CI.

Прогін на Linux: збірка `dotnet build Murmur.sln -c Release` — 0 попереджень, 0 помилок; App 963 зелених, Desktop 49, Core 492; Capture.Windows (нові) 6 пройдено + 4 пропущено; паритет (`Main, Recording, RecordingDark, Onb1Welcome, Onb2Audio, Onb5FirstRecording`) зелений, без змін.

## Не зроблено / перевірити на Windows

Реальне читання SPI і подія `WM_SETTINGCHANGE` на живій системі, а також AOT-публікація win-x64 не перевірялись (лише компіляція під `net11.0-windows`); це покриває CI (`Category=Windows`, `ci.yml`).
